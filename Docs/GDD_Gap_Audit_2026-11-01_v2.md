## 结论

- 主线照样能从头玩到两个结局；**声音层基本补齐了**，坏结局有了 CG。
- 最大的缺口还剩三块：
  1. **出画演出**：空画框里没有实时画面，回头也不会变成《美术馆》。
  2. **布展变化（支柱 3）**：完全没有。
  3. **Lily 的台词**：文字和声音都没有。另外，Lily「出画后才一直盯着你」的时机和 GDD 不一致。
- 统计（第 1 节各表逐行计数，含 §8 计划表）：✅ 58 · 🟡 43 · ❌ 15（上午：✅ 55 · 🟡 38 · ❌ 22）。

## 3. 设计以外的打磨建议（按优先级）

**P0：会影响第一次通关或仓库安全**

1. **未提交改动太多**：工作区有 147 项未提交（不含备份），包括 `Graybox.unity`、两张 NavMesh、`Player.prefab`、十几个脚本，还有一个删除（`NoclipXRay.cs`）。`main` 还停在今天上午的 `e4e52bd`，一旦出意外损失很大。建议另一个 AI 收尾后马上提交一次。
2. **`Docs/Backup` 已经 282 MB**（多份 .unity 场景副本）。如果被 `git add -A` 一起提交，仓库会直接膨胀，接近 GitHub 的限制。建议把 `Docs/Backup/` 加进 `.gitignore`，或者挪出工程目录；`Tools/__pycache__/` 也要忽略。
3. **楼梯断电要先接电话**：玩家不接电话直接上楼会一直卡在闭馆阶段。现在接完电话会有厕所异响和新提示，前半段的引导还缺：电话铃响之前，玩家不一定知道要下楼。

**P1：手感和可读性**

4. 名画人物「二楼必追 + 值班室安全区」让二楼变成固定的往返路线：值班室 ↔ 厕所 ↔ 全家福厅。建议试玩一遍，确认这个节奏是不是你想要的（见第 2 节）。
5. 真结局还是字幕：至少做「全家福画布换成四个人 + 一段八音盒」。
6. 四件供品还是黄色方块，而且一开始就在。
7. 抹脸贴图、Ted 的脸分辨率低（512×256）。

**P2：性能和工程**

8. 视野检测写了好几份（大门、挂钟、监控、名画人物、坏结局 CG），可以抽一个通用组件，后面做布展变化直接用。
9. 实时渲染越来越多：镜子 ×2、监控 6 路，加上手电模型补光、多盏灯。建议在 Windows 低配机实测帧率。
10. 没有打包脚本（Mac / Windows）。

## 4. 下一步推荐（按对第一次完整通关的影响排序）

1. **先提交，并把 `Docs/Backup` 排除掉**：不涉及玩法，但风险最大。
2. **出画演出**：空画框里放实时画面；回头时画框变成《美术馆》，北墙盖布揭开。这是剧情揭示的关键一拍。
3. **Lily 的台词**：画中馆循环播放「The door's open. You'll see it when you come back.」（字幕 + 声音），出画后消失；Lily 肖像改成出画后才盯着你。
4. **布展变化（支柱 3）**：先做一扇门在背后变墙、一幅画在背后换内容。
5. **真结局演出**：全家福变成四个人、《美术馆》里的大人转头、一段八音盒。
6. **定下蹲下、值班室安全区、体力条的去留**，并更新 GDD（§3.1、§4.1、§8 的 ❓）。
7. **文本按阶段开放 + 供品出画后才出现**，避免提前剧透。
8. **打包脚本**，并在 Windows 上测一次帧率。
